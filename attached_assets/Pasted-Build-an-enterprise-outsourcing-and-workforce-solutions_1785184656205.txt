Build an enterprise outsourcing and workforce solutions platform for BluePeak Systems that combines a premium corporate website, a modern careers portal, an internal recruitment application system, a scalable backend, and a production-ready architecture. The finished project must require no additional engineering before deployment other than providing backend credentials and deployment environment variables. Do not leave placeholders, TODO comments, mock implementations, unfinished pages, broken navigation, incomplete styling, missing validations, fake API responses, incomplete routes, or partially implemented components. Every page, workflow, API endpoint, animation, form, upload process, and database interaction must function correctly.

EXECUTION POLICY

Read this entire specification before generating any code. Do not immediately begin generating files after reading the first few instructions. Build a complete internal implementation plan first. Identify all dependencies, routes, pages, APIs, assets, reusable components, services, database requirements, validation requirements, deployment requirements, SEO requirements, accessibility requirements, and user workflows before generating the first file. Generate the project in the correct dependency order so nothing references code that does not yet exist. If additional information is required to complete the backend configuration, stop before generating backend code and request that information from the user. Once all required information has been collected, generate the complete application in one uninterrupted build sequence. Do not intentionally omit features because they appear difficult or lengthy. Continue until every requirement has been implemented.

BACKEND CONFIGURATION REQUIREMENT

Before generating any backend implementation, determine whether persistent data storage is required. Because this application stores applicant information, uploaded resumes, application status, and recruitment records, persistent storage is mandatory. Before implementing the backend, ask the user which backend platform they want to use. Support PostgreSQL, MySQL, SQLite, MongoDB Atlas, Supabase, Firebase, Appwrite, PocketBase, Railway-hosted databases, Render-hosted databases, VPS-hosted databases, and other compatible providers. Ask for every required connection detail including host, port, database name, username, password, connection string, authentication secrets, API keys, storage bucket configuration, upload configuration, and required environment variables. Never invent credentials. Never hard-code secrets. Never generate fake connection strings. Store every secret inside environment variables and generate a complete .env.example file containing every required configuration key.

If the user has not yet selected a backend provider, recommend SQLite only as a temporary development backend while ensuring the storage layer is abstracted so another provider can later replace it without modifying the business logic. Design the application around a repository/service architecture instead of tightly coupling the application to one database engine.
